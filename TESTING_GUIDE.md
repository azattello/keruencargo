# Руководство по тестированию системы статусов для филиалов и клиентов

## Обзор изменений

Система была оптимизирована для работы с ролями филиала и клиента:
- **Статусы ДО "Получено"** теперь показываются с генерированным "Прибыло в филиал"
- **Поиск и фильтрация** оптимизированы для производительности
- **Индексы БД** добавлены для ускорения запросов

## Сценарии тестирования

### 1. Добавление треков (Филиал)

**Шаги:**
1. Войти с ролью `filial`
2. Перейти в раздел "Добавить трек"
3. Проверить список статусов в dropdown

**Ожидаемый результат:**
```
✅ Видны только статусы ДО "Получено" включительно
✅ Первый статус: "Прибыло в филиал [название филиала]"
✅ Можно добавить трек с любым из этих статусов
✅ Нет зависаний при выборе статуса
```

**Пример статусов для филиала:**
```
1. Прибыло в филиал Астана
2. Готов к выдаче
3. Получено
(СКРЫТО) Поступило на склад в Китае
(СКРЫТО) Отправлено в КЗ
```

### 2. Добавление треков (Клиент)

**Шаги:**
1. Войти с ролью `client`
2. Перейти в раздел просмотра треков
3. Проверить список доступных статусов

**Ожидаемый результат:**
```
✅ Видны только статусы ДО "Получено" включительно
✅ Первый статус: "Прибыло в филиал [филиал клиента]"
✅ Статусы отличаются для разных филиалов
```

### 3. Добавление треков (Администратор)

**Шаги:**
1. Войти с ролью `admin` или `china`
2. Перейти в раздел "Добавить трек"
3. Проверить список статусов

**Ожидаемый результат:**
```
✅ Видны ВСЕ статусы (без фильтрации)
✅ Можно добавить трек с любым статусом
✅ Нет сгенерированного "Прибыло в филиал" статуса
```

### 4. Поиск и фильтрация треков

**Шаги:**
1. Перейти в раздел "Все треки"
2. Использовать поиск по различным параметрам:
   - По номеру трека
   - По имени пользователя
   - По телефону
   - По статусу
3. Попробовать фильтровать по статусу

**Ожидаемый результат:**
```
✅ Поиск работает без зависаний (< 1 сек)
✅ Результаты отображаются корректно
✅ Фильтрация по статусу работает правильно
✅ Пагинация работает
✅ Количество треков отображается правильно
```

### 5. Просмотр закладок (Parcels2)

**Шаги:**
1. Войти как клиент
2. Перейти в "Мои закладки" (Parcels)
3. Проверить статусы в списке закладок

**Ожидаемый результат:**
```
✅ Видны закладки с соответствующими статусами
✅ Статус "Прибыло в филиал" отображается правильно
✅ Нет ошибок при загрузке
✅ Пагинация работает
```

### 6. Логика добавления статуса при "Получено"

**Шаги:**
1. Добавить трек со статусом "Получено" (для филиала)
2. Проверить историю трека

**Ожидаемый результат:**
```
✅ В истории появляются два статуса:
   - "Прибыло в филиал [название]"
   - "Получено"
✅ Оба статуса имеют одинаковую дату/время
✅ Порядок правильный (филиальный первый)
```

### 7. Performance тестирование

**Шаги:**
1. Открыть Network tab в DevTools
2. Выполнить:
   - Запрос к `/api/status/getStatus` - проверить размер ответа
   - Запрос к `/api/track/tracks?limit=100` - проверить время ответа
   - Поиск с дебаунсом - проверить отсутствие дублей запросов

**Ожидаемый результат:**
```
✅ /getStatus ответ < 10KB (было ~30KB)
✅ /tracks ответ время < 500ms
✅ Нет дублирующихся запросов в поиске
✅ Индексы используются (проверить в MongoDB logs)
```

## Команды для проверки БД

### Проверка индексов
```bash
db.tracks.getIndexes()
# Должны быть индексы на: trackNormalized, status, user, filial, createdAt
```

### Проверка статусов
```bash
db.statuses.find({ statusText: { $regex: "Получено|Прибыло" } })
# Должны быть "Получено" и "Прибыло в филиал [названия]"
```

### Проверка количества треков
```bash
db.tracks.countDocuments({ status: ObjectId("...") })
# Проверить что counts правильные
```

## Обработка ошибок

### Ошибка: "Статус не найден"
- **Решение**: Убедиться что статус "Получено" существует в БД
- **Проверка**: `db.statuses.findOne({ statusText: "Получено" })`

### Ошибка: "Зависание при добавлении трека"
- **Решение**: Проверить индексы в MongoDB
- **Проверка**: `db.tracks.stats()` - должны быть индексы

### Ошибка: "Неправильный филиальный статус"
- **Решение**: Проверить что `selectedFilial` правильно установлена в User
- **Проверка**: `db.users.findOne({ _id: ObjectId("...") }, { selectedFilial: 1 })`

## Миграция данных

Если нужно убедиться что все старые треки правильно обновлены:

```javascript
// В MongoDB console
db.tracks.updateMany(
  { trackNormalized: { $exists: false } },
  [{ $set: { trackNormalized: { $toUpper: { $replaceAll: { input: "$track", find: /\s+/g, replacement: "" } } } } }]
)
```

## Rollback инструкции

Если нужно откатить изменения:

1. **Откатить индексы:**
   ```bash
   db.tracks.dropIndex("trackNormalized_1")
   db.tracks.dropIndex("status_1")
   # ... и другие
   ```

2. **Откатить роут `/getStatus`:**
   - Восстановить старый код из git history
   - Перезагрузить сервер

3. **Откатить роут `/tracks`:**
   - Восстановить старый код из git history
   - Перезагрузить сервер

## Заметки

- **statusNumber** используется для фильтрации статусов
- Убедитесь что "Получено" имеет правильный statusNumber
- Филиальные статусы автоматически создаются при первом запросе
- Все клиентские компоненты автоматически получают отфильтрованные статусы
